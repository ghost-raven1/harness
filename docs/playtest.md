# Проверка приложения и CLI

Версия Node закреплена в `.nvmrc`. Запускайте команды из корня проекта с этим runtime в `PATH`. Проверки приложения и терминального интерфейса используют отдельные временные каталоги; пользовательские задачи для них не нужны.

## Автоматический набор

```sh
npm ci --include=dev --include=optional --no-audit --no-fund
npm run check
```

Общая проверка включает требования зависимостей, форматирование, TypeScript, сборку и unit/integration-тесты. Подготовка и повторный запуск сборки описаны в [build-stability.md](build-stability.md), проверка исходного ZIP — в [release-stability.md](release-stability.md).

## Настоящий терминал

Базовый сценарий использует стандартную библиотеку Python:

```sh
python3 scripts/playtest-cli.py --node /полный/путь/к/node
```

Для сценариев, которые проверяют видимый кадр, подготовьте отдельное Python-окружение:

```sh
python3 -m venv .tools/cli-test-python
.tools/cli-test-python/bin/python -m pip install pyte==0.8.2
.tools/cli-test-python/bin/python scripts/playtest-source-bugs.py --node /полный/путь/к/node
```

Эти команды рассчитаны на macOS/Linux. В Windows пути и терминальную автоматизацию нужно адаптировать к нативному окружению. Сборка должна быть готова до запуска PTY и не должна меняться во время прохода.

[Карта экранов](screen-audit.md) связывает маршруты с воспроизводимыми сценариями. Отдельно доступны проверки первого запуска (`playtest-beginner.py`), живых обновлений (`playtest-live-screens.py`), читаемости (`playtest-readability.py`), выхода (`playtest-polish.py`), продолжения беседы (`playtest-answer.py`) и порций шагов (`playtest-iterations.py`).

Сценарии создают свежие отчёты в `docs/` и кадры в проектном `.harness/`. Это одноразовые материалы конкретной сборки: после анализа их можно удалить. Журналы и настройки пользовательского каталога состояния к этим артефактам не относятся.

## Внешние клиенты и модели

- `npm run playtest:opencode` проверяет взаимодействие с настоящим OpenCode.
- `npm run playtest:codex` проверяет маршрут MCP → Harness → Codex; использует текущую авторизацию и расходует лимит аккаунта.
- `npm run playtest:cloud` обращается к облачному провайдеру; требует соответствующей конфигурации и ключа.

Успешный локальный набор не подтверждает работу внешнего аккаунта или другой ОС. Облачные проверки запускайте осознанно и учитывайте их расходы отдельно. Подключение Codex описано в [codex.md](codex.md), восстановление после ограничения провайдера — в [coordination-and-recovery.md](coordination-and-recovery.md).
