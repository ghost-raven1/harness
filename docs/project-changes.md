# Изменения файлов и учебное демо · 0.6.0

В карточке проекта выберите **«Изменения файлов · до и после»**, затем промежуток и файл. Вкладки показывают построчные изменения, исходный текст и итоговый текст. Табуляция переключает вкладки; стрелки прокручивают текст; Enter открывает страницы и связанные проверки. Сравнение привязано к сохранённым точкам: новые результаты не меняют уже открытый текст.

## Что сравнивается

Доступны весь проект от исходной папки, отдельные попытки этапов, проверочные команды, паузы и внешние изменения перед продолжением. Исходная точка включает незакоммиченные файлы; Git не требуется. Перемещения отображаются как удаление и добавление. Изменения типа файла и права исполнения показываются отдельно.

Это изменения **за промежуток времени**, а не доказательство авторства агента. Редактор или внешняя программа могли изменить ту же папку. Отдельный интервал внешних изменений помогает увидеть разницу между паузой и продолжением.

Просмотр не меняет рабочие файлы и не создаёт контрольные точки. Общий откат папки в этот выпуск не входит. Приёмка сохраняет прежние проверки и повторную сверку актуальности файлов. Неполное сравнение само по себе не запрещает принять проверенный результат.

## Содержимое и ограничения

Для новых проектов сохранение включено по умолчанию. Его можно отключить в параметрах перед исполнением. Для уже запущенного проекта сначала завершите паузу; настройка действует только на будущие точки. Исторические проекты открываются без миграции и без восстановления прошлого текста из текущей папки: сохранение для них включается явно.

В главном конфигурационном манифесте:

```json
{
  "projects": {
    "capture": {
      "enabled": true,
      "fileBytes": 1048576,
      "projectBytes": 104857600,
      "totalBytes": 1073741824
    }
  }
}
```

Предел файла — 1 МиБ по умолчанию, максимум 4 МиБ. Уникальное содержимое одного проекта ограничено 100 МиБ, всего Harness — 1 ГиБ. Одинаковые байты переиспользуются только внутри одного проекта. При достижении настроенного предела выполнение продолжается с хешами и отметкой об отсутствии текста; прежние копии автоматически не удаляются.

Копируются только обычные UTF-8-файлы, на чтение которых закреплённая политика даёт `allow`. Запрос `ask` не считается разрешением на автоматическую копию. Ссылки не обходятся; двоичные, большие файлы, неподдерживаемая кодировка, известные пути секретов и служебные каталоги исключаются. В частности, не сохраняются приватные SSH-ключи и `.aws/credentials`. Фильтр путей не распознаёт секрет, вручную вписанный в обычный исходник: такие файлы нужно исключить правилами. Карточка объясняет причину отсутствия текста. Повреждённая или пропавшая копия не подменяется содержимым рабочей папки.

Реальный отказ записи, например заполненный диск или ошибка `fsync`, останавливает сохранение по обычным правилам отказа хранилища. Это отличается от настроенного лимита копий. После аварии уже сохранённая точка связывается с запуском; если точное состояние утрачено, остаётся явный пробел. Команды ради получения снимка не повторяются.

## Команды и экспорт

```sh
harness projects change-sets PROJECT_ID
harness projects changes PROJECT_ID CHANGE_SET_ID
harness projects file-change PROJECT_ID CHANGE_SET_ID FILE_ID --view diff
harness projects file-change PROJECT_ID CHANGE_SET_ID FILE_ID --view before
harness projects capture PROJECT_ID off --revision REVISION --key REQUEST_KEY
```

Точные параметры доступны через `--help`. Локальный протокол объявляет возможность `projects-diff-v1`; со старым сервисом новые действия скрыты. Три публичных инструмента MCP остаются прежними.

В экспорте включите **«Включить построчные изменения»** или CLI-опцию `--include-diffs`. Она выключена по умолчанию и добавляет общий итоговый diff, без истории всех попыток. Предпросмотр показывает состав и недоступные сравнения. Журналы stdout/stderr включаются независимо. Отчёт публикуется атомарно в `exports/projects/<projectId>` внутри состояния Harness.

Удаление проекта и выбранный сброс охватывают сохранённые исходники, индексы, кэш, экспорты и временные файлы. Самостоятельно скопированные наружу отчёты Harness не удаляет.

## Учебная корзина

Запустите `harness demo` или пункт главного меню **«Попробовать на учебном проекте»**. Учебный провайдер работает без сети и ключей, но использует настоящий runtime, файловые инструменты, проверочные команды, журналы и формы.

1. Начните учебный проект и подтвердите его параметры.
2. Просмотрите план исправления расчёта `120 × 3 = 360`, примите план.
3. Посмотрите провал исходного теста и неудачную первую попытку. Harness запустит исправление и проверит его тем же тестом.
4. Откройте изменения файла `price.js`, исходный текст и результат. Посмотрите сохранённые проверки.
5. Примите результат и попробуйте экспорт.
6. Выйдите из демо. Его исполнители завершатся, временная папка и отчёты удалятся.

Все экраны обозначены **ДЕМО**. Произвольные задания этот провайдер не выполняет; доступны только учебная папка и фиксированная команда теста. Обычные подключения, настройки и задачи не меняются. Повторный запуск начинает чистый сценарий.

## Для разработчика

`ProjectWorkspace` сохраняет прежний формат хешей и передаёт байты из того же проверенного чтения в `ProjectChangeContentStore`. Содержимое хранится в `project-content/<projectId>/blobs`, новые манифесты — рядом в `manifests`. `ProjectChangeRecorder` привязывает точки к намерениям и завершениям исполнителей. Все ссылки публикуются после атомарной записи файлов; журнал остаётся источником истины.

`ProjectChangeService` проверяет принадлежность проекта, интервала и файла. Произвольные пути клиенту недоступны. `ProjectDiffWorker` объединяет одинаковые запросы, держит один worker, очередь до восьми запросов и кэш до 16 МиБ. Вычисление ограничено секундой и 10 000 изменённых элементов; при превышении остаются вкладки полного сохранённого текста. Страницы содержат не более 16 384 символов и не разрывают пары Unicode.

Демо собрано отдельными модулями: подготовка папки в `application/demo.ts`, детерминированный адаптер в `providers/demo-provider.ts`, интерфейс и владение сервисом в `interfaces/commands/demo.ts`. Провайдер восстанавливает этап из истории, а не из счётчика процесса. В главном меню демо запускается отдельным дочерним процессом, чтобы его завершение не останавливало обычные задачи.

Проверки: `test/demo.test.ts`, `test/project-change-*.test.ts`, `test/project-diff*.test.ts`, `test/project-diff-export-060.test.ts`; настоящий терминал — `scripts/playtest-demo.py` и `scripts/playtest-project-diff.py`. Последние запускаются после сборки с Python-окружением `pyte==0.8.2`, в размерах 48×24 и 80×24.

`scripts/playtest-demo-signals.py` отдельно проверяет ранний SIGTERM, сигнал в открытом меню, освобождение временной папки и восстановление ECHO/ICANON. Ему достаточно стандартной библиотеки Python на Linux/macOS.

## Локальный стенд перед выпуском

Замер 20 сентября 2026 года на macOS, Node.js 24.21.0: 10 000 задач, 100 сохранённых попыток, фоновая очередь тяжёлых сравнений. Другие тесты во время замера не выполнялись.

| Запрос IPC       |      p95 |
| ---------------- | -------: |
| Список задач     |  52,5 мс |
| История задач    |  54,7 мс |
| Список проектов  |  65,4 мс |
| Сведения сервиса | 166,2 мс |

Холодный старт — 17,2 с, RSS — 391 МБ, хранение — 292 МБ. Запросы меню не прочитали ни одной переписки. Шесть тяжёлых сравнений были явно остановлены по вычислительному пределу; просмотр до/после остаётся доступным. Кэш занял 3 432 байта при пределе 16 МиБ. Это замер macOS; целевой порог Linux CI проверяется отдельно командой `npm run benchmark:diff -- 10000`.

Тот же стенд прошёл на Linux в [проверке ветки `c40ee76`](https://github.com/ghost-raven1/harness/actions/runs/35457407988), задание **Project diff and demo**: p95 списка задач — 51,4 мс, истории — 57,7 мс, проектов — 48,4 мс, сведений сервиса — 160,0 мс. Чтений переписок — 0; холодный старт — 13,6 с, RSS — 458 МБ. Все четыре запроса уложились в 200 мс. Это результат отдельного стенда, а не подтверждение всей матрицы указанного коммита.

Повторная проверка выявила лишнее копирование каталога в `system.info`: три копии на один запрос. Счётчики теперь используют один снимок каталогов внутри запроса, сохраняя актуальность следующего чтения. После исправления повторный замер на macOS дал p95 `system.info` 62,3 мс, остальных запросов — 48,5–75,5 мс; чтений переписок — 0. Порог Linux CI остался прежним.
