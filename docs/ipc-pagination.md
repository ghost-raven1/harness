# Большие ответы локального сервиса

Запрос проверяется до открытия сокета: он должен сериализоваться в JSON и занимать не больше 1 200 000 байт вместе с оболочкой. Ответ локального канала ограничен 8 MiB; увеличение сохранённой истории этот предел не меняет.

Обычный `result` размером до 256 KiB в JSON передаётся полностью, как раньше. Для большого ответа `runtime.status` и `runtime.task` возвращают первую часть в `result`, `resultTruncated: true`, `resultLength` и `resultPage`. Страница содержит `text`, `cursor`, `nextCursor`, `total`, `hasMore`. Размер текста страницы в JSON не превышает 256 KiB.

Все курсоры и длины текста измеряются в кодовых единицах UTF-16. Используйте возвращённый `nextCursor`: граница никогда не разделяет суррогатную пару. Локальный `runtime.result({ runId, cursor })` возвращает очередную страницу. Через MCP используйте прежний `harness.status` с дополнительным `resultCursor`; новые MCP-инструменты не добавляются. Читается ответ указанного запуска, без перехода на последний запуск беседы.

CLI показывает большие ответы частями. Enter открывает выбор следующей или предыдущей части. Действие сохранения сначала дочитывает ответ и никогда не записывает preview как полный файл. Команда `harness answer <runId>` выводит полный ответ, в том числе при перенаправлении в файл.

`runtime.list` сохраняет формат массива и принимает необязательные `offset` и `limit` (до 200 записей). CLI использует страницы. В списках и истории длинный текст задачи заменяется коротким описанием с `taskTruncated: true`; полный текст доступен в `runtime.status.task`. Поиск и счётчики используют исходный текст.

Сохранённые задачи, ответы и журналы не сокращаются. Если другой маршрут формирует ответ свыше 8 MiB, сервис возвращает явную ошибку и остаётся доступным: автоматического обрезания произвольных данных нет. Для больших коллекций запрашивайте отдельную запись или поддерживаемые страницы.
