# Следующий этап: доверенные контрольные наборы обучения

Предложение после измерения специалистов; управление наборами не входит в 0.6.0.

## Исходное наблюдение

В поставляемом `config/learning.json` массив `cases` пуст. При таком исходном состоянии автоматическое обучение не располагает независимыми контрольными задачами для подтверждения улучшения. Это недостаток исходных доказательств, а не основание ослаблять оценку. Тесты текущего оценщика проверяют механизм; они не доказывают пользу конкретного урока на пользовательских проектах.

## Пользовательский путь

1. Открыть неактивный кандидат и увидеть точную причину: нет доказательства, целевого случая, подходящего независимого набора либо сравнение выявило регрессию.
2. Создать черновик набора из доверенных задач: вход, роль, профиль, область применения, фиксированные инструменты и ожидаемые результаты. Целевые и независимые случаи задаются отдельно.
3. Проверить схему и показать состав перед принятием человеком. Модель не получает право утверждать ожидания или менять принятый набор.
4. Запустить проверку самого набора в изолированном тестовом исполнителе с подменёнными внешними действиями. Ошибки инфраструктуры отличать от ошибки урока.
5. Сохранить неизменяемую версию набора, затем явно повторить оценку кандидата. Текущий опыт и кандидат сравниваются трижды на каждой версии; публикация сохраняет существующие требования отсутствия новых провалов и улучшения целевого случая.
6. Открыть отчёт «случай → ожидание → фактический результат» и причины решения. Подтверждённая регрессия отзывает выпуск для будущих запусков.

## Хранение и границы

Модуль learning хранит версии наборов, область доверия и связь с отчётами. Application связывает создание, проверку, удаление и восстановление. Runtime получает обычные фиксированные задания, не импортируя модуль обучения. Формат JSONL сохраняется; исторические отчёты получают необязательную связь с версией набора.

Принятые ожидания не передаются генератору уроков. Доказательства проверяются по исходным событиям и артефактам. Набор не меняет машинные политики, авторские инструкции и права инструментов. Файлы рабочей папки не считаются автоматически доверенными контрольными ожиданиями.

Активный запуск сохраняет закреплённую версию опыта. Очередь оценки последовательная, восстанавливаемая, с отменой и повтором по устойчивому ключу. Новые токеновые квоты не вводятся. Управление доверием остаётся действием человека через CLI; публичные инструменты MCP не расширяются.

## Измерения до расширения

- Доля кандидатов, остановленных каждой проверкой, с отдельной категорией отсутствующих данных.
- Продолжительность и фактический usage извлечения и оценки, число повторных запросов, 429 и прерванных сравнений.
- Число улучшенных целевых случаев и новых провалов независимых случаев; число отзывов выпусков.
- Стабильность результата при трёх повторах; единичный удачный ответ не считается улучшением.

Первые измерения выполняются на явно принятом небольшом наборе. До них нельзя обещать рост качества или определять цель числом опубликованных уроков.

## Проверки поставки

Подмена ожиданий, пересечение целевого и независимого набора, неизвестная роль, чужая область workspace, устаревшая ревизия из второго окна, повтор отправки после потери ответа, авария между оценкой и публикацией, отзыв и повторная обработка событий. Экспорт исключает секреты подключения; выбранное удаление охватывает версии, индексы и кэши без повреждения уже закреплённого опыта активной задачи.
