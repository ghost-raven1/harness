# Проверка читаемости и поддержки

## Исходное состояние

Главные сложности: плотные однострочные блоки, несколько действий в строке, длинный цикл агента вместе с управлением деревом, CLI-команды в одном замыкании, повторные вычисления результатов оценки и неявное владение состоянием. Счётчик строк скрывал объём обязанностей файлов.

## План изменений

1. `runtime/engine.ts`: оставить жизненный цикл запуска; выделить цикл модели и инструментов в `runtime/agent-loop.ts`, дочерние задачи и handoff — в `agents/coordinator.ts`, создание снимка запуска — в `runtime/run-factory.ts`.
2. `interfaces/cli.ts`: оставить сборку команд. Команды запуска, сервиса, обучения и интерактивного меню разместить рядом в `interfaces/commands/`. Типы интерфейса и логотип вынести в отдельные файлы этой же функциональности.
3. `learning/evaluator.ts`: разделить выбор набора, продолжение отчёта, проверку ожидаемого результата и решение о публикации на явно названные шаги.
4. Применить Prettier к исходникам и тестам, включить проверку форматирования и неиспользуемых переменных. После форматирования пересмотреть файлы, превышающие 500 строк.
5. Проверить сохранение поведения по исходному набору тестов, дополнить отсутствующие проверки границ, повторить OpenCode, аварийное восстановление и интерактивный CLI.

API CLI/MCP и формат сохранённых данных сохраняются. Новые внутренние файлы отвечают за конкретный этап исполнения; универсальный фреймворк обработчиков не вводится.

## Выполнено

| Участок   | Результат                                                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime   | Конструктор принимает именованные зависимости. Создание запуска, жизненный цикл, цикл одной роли и координация дерева находятся в отдельных файлах.                 |
| CLI       | Команды разнесены по задачам; общие параметры и типы описаны явно. Собственный логотип H адаптируется к ширине окна.                                                |
| Вывод     | Карточки переносят длинные строки без потери текста аргументов. JSON и MCP не получают логотип или ANSI-оформление.                                                 |
| Обучение  | Продолжение отчёта, проверка ответа и принятие решения о публикации разделены на именованные шаги.                                                                  |
| Хранилища | Общая запись JSONL выполняет fsync; чтение сохраняет завершённые события и отбрасывает оборванный хвост. Доменные проверки остаются в хранилищах.                   |
| Стиль     | Prettier закреплён в зависимостях; включены `noUnusedLocals` и `noUnusedParameters`. В исходниках и тестах нет явного `any`, подавления TypeScript и TODO-заглушек. |

Перенос строк использует [wrap-ansi 9](https://github.com/chalk/wrap-ansi/tree/v9.0.0), чтобы не разрывать управляющие последовательности цвета. API модели и формат состояния при рефакторинге не менялись. В режиме `--json approvals` команда возвращает список, не открывая интерактивный диалог.

На момент первого рефакторинга крупнейшим исходным файлом был `learning/service.ts` (261 строка). После развития CLI состав и размеры изменились. Актуальные границы и следующие шаги описаны в [архитектурном плане](architecture-roadmap.md); размер файла остаётся поводом проверить его обязанности, а не целью дробления.

## Найденные и исправленные сбои

1. Повреждённый `learning.json` не позволял восстановить исправный журнал. Теперь сначала читается журнал; снимок используется только при отсутствии завершённых событий. Отдельный тест воспроизвёл ошибку до исправления.
2. Каталог вместо `control.sock` приводил к утечке блокировки запуска сервиса. Подготовка сокета теперь находится внутри участка с гарантированным освобождением блокировки. Проверены отказ и следующий успешный запуск.
3. Длинный путь в карточке разрешения выходил за границы терминала. Добавлен перенос; проверены ширины 20, 40 и 80 колонок, включая сохранность аргументов.
4. `--json approvals` мог открывать интерактивные вопросы. Теперь этот режим только читает список решений.

## Рабочий стол для первого запуска

Обычный вход вынесен в `interfaces/guided/`: выбор папки, подключение модели, временные ключи, владение сервисом, задачи, ожидание и настройки имеют отдельные файлы. Расширенные команды и MCP используют прежние контракты. Состояние выбора рабочего стола сохраняется отдельно от журналов задач.

Подготовка использует Ora с `discardStdin: false`, а живой просмотр задачи — log-update в отдельном буфере терминала. Клавишами управляет рабочий стол. Это устраняет обнаруженный в живом терминале безусловный выход из процесса при Esc в индикаторе Clack. Перед вопросом разрешения обработчик клавиш снимается, режим терминала восстанавливается.

Отмена помечается в памяти до вызова AbortController. Поэтому мгновенный отказ API не может поставить `failed` поверх ещё записываемого `cancelled`. Регрессионный тест проверяет состояние агентов и отсутствие ложного события ошибки.

Диагностика выбирает конфигурацию подключённого сервиса. Её отрицательный результат внутри меню не превращает последующий штатный выход в ошибку файла запуска.
