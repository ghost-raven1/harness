# Проекты: от цели до принятого результата

Проект сохраняет цель, принятый план, этапы и доказательства проверок. Рабочая папка остаётся обычной папкой на вашем компьютере. Для короткого вопроса по-прежнему подходит «Новая задача»; для работы с несколькими этапами откройте «Проекты».

## Первый проект

1. Откройте **Проекты → Новый проект** и опишите желаемый результат. Enter добавляет строку, Ctrl+S сохраняет описание для следующего шага, Esc сохраняет черновик.
2. Проверьте название, папку и профиль модели. Их можно изменить перед **Подготовить план**. Доступны разрешённые папки и настроенные профили; глобальный выбор модели не меняется. До подтверждения модель не вызывается.
3. Harness исследует выбранную папку инструментами чтения и предложит план.
4. Откройте план: проверьте роли, зависимости этапов, ожидаемый результат и способы проверки. Редактор позволяет добавить, скопировать или удалить незавершённый этап, изменить его задачу и проверки без JSON.
5. Команда и каждый её аргумент вводятся отдельно. Например, для `node --test` команда — `node`, аргумент — `--test`. Пробел внутри аргумента сохраняется; дополнительные кавычки для оболочки не нужны.
6. Сохраните редакцию целиком. Она создаёт одну версию и не запускает работу. Перед принятием просмотрите сравнение: отдельно показаны порядок этапов, роли, зависимости, команды и критерии.
7. Выберите **Принять план и начать**. Harness проверит исходное состояние, выполнит этапы и проверит результаты. Ручная проверка требует вашего подтверждения.
8. Откройте итог приёмки: **Ожидалось → Получено → Подтверждено**. После просмотра доказательств примите результат; ответ модели «готово» не заменяет проверки.

Список, карточка проекта, план, проверки и журнал обновляются при работе другого окна. Tab переключает разделы, ↑↓ и PgUp/PgDn прокручивают текст, Esc возвращает назад. Журнал, публичные пояснения модели и полный ответ конкретного этапа открываются через **Журнал, мысли и ответ этапа**. В карточке проекта хранится ограниченное окно последних загруженных событий; полные события доступны страницами через `projects show --cursor`.

## Черновики и два окна

Описание, параметры создания и редакция плана сохраняются в состоянии Harness. Отмена формы не вызывает модель и не запускает этапы. После подтверждения закрепляются весь запрос и его ключ: повтор после потери связи отправляет те же данные.

Если другое окно изменило проект, ввод остаётся в черновике. Устаревшую редакцию нельзя отправить: сначала просмотрите сравнение с текущей версией. Автоматического слияния нет. Новый черновик ограничен 900 КиБ, чтобы полный запрос помещался в локальный канал. Завершённые этапы доступны для чтения; новую работу оформляйте новым этапом, в том числе копированием.

## Требует решения

В списке проектов доступен фильтр со счётчиком ожидающих решений. Причина ведёт к принятию плана, разрешениям, ручной проверке, разбору ошибки или приёмке. Неизвестный результат операции и отказ хранения показываются первыми. Ограничение провайдера отображается отдельно; если сервис получил время повторной попытки, оно также показывается. Harness не продолжает проект автоматически.

## Полный вывод проверок

Список проверок разделяется по исходному прогону, этапу и итоговому прогону; у каждой записи сохраняется попытка. Карточка показывает точную команду и массив аргументов, состояние, код завершения и связанный запуск. stdout и stderr открываются отдельно, страницами по 16 384 символа. Текст после первых 1 500 символов также доступен.

Исполнитель сохраняет до **1 048 576 символов отдельно для stdout и stderr**. При превышении явно показано обрезание; отсутствующая часть не восстанавливается. Пока команда выполняется, виден её статус. Потоковой трансляции вывода команды нет. Недоступный или чужой артефакт обозначается как недоступное доказательство, а не успешная проверка. Управляющие последовательности терминала не исполняются при просмотре.

При открытии приёмки Harness сверяет рабочие файлы с проверенным состоянием и показывает время сверки. Просмотр не создаёт новые снимки. Перед подтверждением проверка повторяется: изменившаяся папка требует нового прогона. Старые попытки отделены от доказательств принимаемого результата. С версии 0.6.0 доступен [построчный просмотр файлов, этапов и проверок](project-changes.md). Полного отката папки нет.

## Экспорт результата

Выберите формат Markdown или JSON и просмотрите состав. По умолчанию входят цель, принятый план, результаты этапов, изменения и проверки. Полные сохранённые stdout/stderr добавляются отдельной опцией **включить журналы**, вместе с отметками обрезания. Предпросмотр показывает пользовательские команды и состав журналов; они могут содержать ваши данные.

Отчёт сохраняется в `<state>/exports/projects/<projectId>`, вне рабочей папки, и не делает проверки файлов устаревшими. Конфигурации, переменные окружения и ключи подключения не добавляются. Существующий файл не перезаписывается; повтор того же запроса возвращает тот же экспорт. Изменение проекта после предпросмотра требует нового подтверждения. Самостоятельно скопированный наружу отчёт Harness не удаляет.

## Пауза, ошибки и изменения файлов

- **Приостановить** сохраняет состояние и ждёт завершения текущих операций. **Продолжить** проверяет, не изменились ли файлы за время паузы.
- Если карточка показывает **Ждёт разрешения**, откройте **Рассмотреть разрешения**. Проверка или действие начнётся только после вашего решения; принятие плана не отменяет эти запросы.
- При внешних изменениях просмотрите состав и подтвердите продолжение. Старые проверки не доказывают корректность нового состояния: для приёмки нужна повторная проверка.
- Если исходные проверки не проходят, выберите **Включить исправление исходных ошибок в план**, затем примите новую версию плана. Harness не считает старую ошибку успешно выполненной работой.
- При исчерпании исправлений проект ждёт решения. По умолчанию разрешены две попытки исправления; предел меняется в плане.
- При неизвестном результате прерванной операции откройте **Проверить прерванную операцию**. Проверьте фактический эффект и зафиксируйте исход. Такая операция автоматически не повторяется.
- Сообщение работающему этапу передаётся через **Уточнить работающему этапу**. Оно адресовано конкретному этапу; Harness не переносит его автоматически в следующий этап.
- После аварийного завершения работа автоматически не продолжается. Откройте сохранённый проект, проверьте его состояние и продолжите явно.

Окно-владелец при выходе закрывает сервис и приостанавливает проекты. Подключённое второе окно только отключается. Для работы в фоне оставьте отдельное окно `serve`.

## Архив и удаление

**Убрать в архив** скрывает проект из основного списка; **Показать архив** позволяет открыть и вернуть его. **Удалить навсегда** показывает предпросмотр связанных задач, бесед и артефактов. Подтверждение относится к этому составу и перестаёт действовать при изменении данных в другом окне. Каскад также удаляет историю проекта, черновики, производные индексы и управляемые экспорты. Сброс задач охватывает эти же данные; сброс только знаний их сохраняет. Рабочие файлы проекта остаются на диске.

Управляемые проектом задачи открывают карточку проекта для паузы, продолжения, сообщений и удаления. Это сохраняет связи плана и проверок. Проектные команды не экспортируются модели через MCP.

## Команды для скриптов

Команды подключаются к работающему локальному сервису. Перед `projects` добавляйте `npm start --` либо `node dist/interfaces/cli.js`. Флаг `--json` включает машинный ответ.

```bash
npm start -- --json projects create "Страница ошибок" "Добавить понятную страницу ошибки и проверить её" --workspace /путь/к/папке --key create-001
npm start -- --json projects show PROJECT_ID
npm start -- --json projects plan PROJECT_ID --revision 1 --key plan-001
```

Ревизию всегда берите из актуального `show`. При повторе запроса после потери связи сохраняйте **весь исходный payload, прежние `--revision` и `--key`**. Для нового решения используйте новый ключ. Версия плана (`--plan-version`) и отпечаток проверенных файлов (`--result-revision`) независимы от ревизии карточки.

| Команда                                            | Дополнительные параметры                                                            |
| -------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `projects list`                                    | `--query`, `--page` с нуля, `--archived`, `--attention`                             |
| `projects show PROJECT_ID`                         | `--cursor` для следующей страницы событий                                           |
| `projects create TITLE GOAL`                       | `--workspace`, `--profile`, `--key`                                                 |
| `projects plan PROJECT_ID`                         | `--revision`, `--key`, необязательные `--feedback` и `--goal`                       |
| `projects edit PROJECT_ID`                         | `--revision`, `--key`, `--file plan.json`                                           |
| `projects accept-plan PROJECT_ID`                  | `--revision`, `--key`, `--plan-version`                                             |
| `projects pause PROJECT_ID`                        | `--revision`, `--key`                                                               |
| `projects resume PROJECT_ID`                       | `--revision`, `--key`, `--accept-changes` после просмотра изменений                 |
| `projects cancel PROJECT_ID`                       | `--revision`, `--key`                                                               |
| `projects message PROJECT_ID STAGE_ID TEXT`        | `--revision`, `--key`                                                               |
| `projects manual-check PROJECT_ID STAGE_ID`        | `--revision`, `--key`, `--result-revision`, `--outcome passed\|failed`, `--comment` |
| `projects recheck PROJECT_ID`                      | `--revision`, `--key`                                                               |
| `projects accept PROJECT_ID`                       | `--revision`, `--key`, `--result-revision`                                          |
| `projects archive PROJECT_ID`                      | `--revision`, `--key`, `--restore` для возврата                                     |
| `projects purge-preview PROJECT_ID`                | Показывает состав и токен удаления                                                  |
| `projects purge PROJECT_ID`                        | `--revision`, `--key`, `--preview-token`                                            |
| `projects resolve PROJECT_ID RUN_ID INVOCATION_ID` | `--revision`, `--key`, `--result`, `--outcome succeeded\|failed`                    |

Новые команды просмотра и экспорта:

| Команда                                               | Параметры                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `projects reports PROJECT_ID`                         | `--phase baseline\|stage\|final`, `--stage`, `--attempt`, `--offset`                                               |
| `projects check-output PROJECT_ID REPORT_ID CHECK_ID` | `--stream stdout\|stderr`, `--offset` из предыдущего `nextOffset`                                                  |
| `projects review PROJECT_ID`                          | Итог и свежая проверка файлов                                                                                      |
| `projects plan-versions PROJECT_ID`                   | `--offset`                                                                                                         |
| `projects compare-plans PROJECT_ID`                   | `--from`, `--to`; по умолчанию сравнение с последней принятой версией, иначе с предыдущей                          |
| `projects validate-plan PROJECT_ID --file plan.json`  | Необязательный `--revision`; результат содержит `valid`, `stale`, `issues` с путями полей и нормализованный `plan` |
| `projects export-preview PROJECT_ID`                  | `--revision`, `--format markdown\|json`, необязательный `--include-logs`                                           |
| `projects export PROJECT_ID`                          | Те же параметры, `--preview-token` и `--key`                                                                       |

Расширенное редактирование через JSON требует объект с `stages`, `maxCorrections`, `fixBaselineFailures`, без `version`. Формат проверяется по `src/projects/schema.ts`; роли и инструменты должны существовать в конфигурации. В обычном интерфейсе знание JSON не требуется.

## Границы для разработчиков

`projects/schema.ts` определяет контракты, `ProjectService` проверяет решения человека, координатор управляет этапами через внутренний порт runtime. Прикладной обработчик `application/commands/projects.ts` использует доменные схемы; CLI и IPC используют их же через типизированный реестр. Отдельные файлы в `interfaces/guided/project-work/` отвечают за представление, план, проверки, действия, черновики и навигацию.

Перед мутацией проверяются ревизия и ключ. Принятие плана дополнительно закрепляет его версию; приёмка — отпечаток файлов. Подтверждение на экране содержит неизменный снимок, а опрос сервиса проверяет его актуальность. Черновики используют `purpose`, `projectId`, `stageId`; отправленный черновик также сохраняет `expectedProjectRevision`. Очередь проекта берётся перед очередью файлов состояния, как при каскадном удалении.

Состояние проектов хранится отдельно в `project-records`. Переписки этапов остаются в обычных задачах. Старый каталог `projects` с настройками подключений не переносится и не переименовывается.

### Чтение доказательств в 0.5.0

`ProjectPlanService` отвечает за проверку, историю и сравнение; `ProjectEvidenceService` — за принадлежность и страницы результатов. Чтение проверяет цепочку «проект → отчёт → запуск → вызов → артефакт». Декодированный вывод ограничен кэшем 16 МиБ, исходный JSON — 16 МиБ; параллельные запросы одного результата объединяются. Лимит исполнителя остаётся 1 048 576 символов на каждый поток.

`ProjectExportService` в application сериализует публикацию с удалением и сбросом. Новый каталог `<state>/exports/projects/` принадлежит приложению; отчёт публикуется атомарно без перезаписи, квитанция поддерживает повтор запроса. При каскаде очищаются производные данные и память читателей.

Индекс редакций `<state>/project-index/<projectId>.plans.json` хранит смещения и контрольные суммы, а не копии полных планов. Его можно пересоздать из исходного JSONL; исторические конфигурации и версия опыта не меняются. Новые действия CLI доступны только при объявлении `projects-review-v1` в `system.info`. Протокол остаётся версии 1; MCP по-прежнему предоставляет только `harness.run`, `harness.status`, `harness.cancel`.

Стенд `npm run benchmark:projects -- 100` или `-- 1000` создаёт временные проекты и проверяет холодный запуск, RSS, размер хранения, p95 списка и счётчиков. Во время запросов меню чтение истории запрещено самим стендом. На Linux CI действует предел p95 200 мс.
