# Диагностика истории и индексов

Обычный `harness doctor` проверяет Node.js, конфигурацию и доступность локального сервиса. Проверка не отправляет задачи облачной модели. Наличие ключа и возможность выполнить платный запрос — разные проверки: доступ к модели проверяется при выполнении задачи.

## Проверка сохранённых данных

```sh
harness doctor --verify-history
harness --state /папка/состояния doctor --verify-history
```

Проверяются журналы задач, связи агентов и операций, последовательность событий, опубликованный вывод модели и сохранённое обучение. Результат содержит количество проверенных записей, коды обнаруженных проблем и идентификатор повреждённой задачи. Проверка не обрезает оборванные строки, не заменяет журнал снимком и не переписывает конфигурацию или версию опыта. Подтверждённые маркеры удаления имеют приоритет над оставшимися после сбоя файлами.

Когда сервис работает, CLI передаёт проверку владельцу состояния. Без работающего сервиса команда временно захватывает ту же блокировку каталога. Два процесса не могут одновременно восстанавливать одни данные. Не удаляйте `daemon.lock`, пока запущен сервис.

Незавершённые операции с неизвестным результатом учитываются отдельно. Это не повреждение формата, но перед продолжением соответствующей задачи человек должен проверить фактический результат. Диагностика не повторяет операции.

Основные коды:

| Код                           | Значение и следующее действие                                                                                                                             |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JOURNAL_TORN_TAIL`           | Последняя строка оборвана. Сохраните диагностический отчёт; только запуск владельца состояния может удалить неподтверждённый хвост перед восстановлением. |
| `JOURNAL_INVALID_RECORD`      | Завершённая запись не соответствует формату. Оставьте сервис в режиме просмотра и исследуйте причину повреждения.                                         |
| `JOURNAL_INVALID_SEQUENCE`    | Нарушена последовательность событий. Продолжение по старому снимку небезопасно.                                                                           |
| `STORAGE_VERSION_UNSUPPORTED` | Данные имеют неизвестную версию. Используйте совместимую версию приложения.                                                                               |
| `HISTORY_INVALID_LINK`        | Запись ссылается на отсутствующую задачу, агента или другую обязательную запись.                                                                          |
| `STORAGE_UNAVAILABLE`         | Нет доступа к данным или произошёл отказ диска. Устраните проблему хранения и повторите проверку.                                                         |
| `STORAGE_UNSAFE_PATH`         | Внутренний файл или каталог заменён ссылкой. Проверьте расположение данных.                                                                               |
| `INDEX_REBUILD_FAILED`        | Источник сохранился, но производный индекс не удалось записать. Проверьте доступ и свободное место.                                                       |

## Перестроение индексов

```sh
harness doctor --rebuild-index
harness doctor --rebuild-index --verify-history
```

Команда перестраивает производные данные под блокировкой владельца. Журналы, авторские настройки и снимки задач не ремонтируются. При отсутствии сервиса инициализация для обслуживания выполняется без аварийного восстановления и не запускает агентов. Повреждённый источник нельзя сделать исправным перестроением индекса.

## Отчёт для поддержки

```sh
harness doctor --export harness-diagnostic.json
harness --json doctor --verify-history --export harness-diagnostic.json
```

`--export` включает проверку истории. Файл содержит версии клиента и доступного сервиса, идентификаторы сборок, версии протокола и хранения, ОС, результаты проверок, счётчики и коды ошибок. Сборка исходников без готового манифеста имеет `buildId: null`.

В экспорт не включаются тексты задач и ответов, содержимое инструментов, ключи, имена профилей, идентификаторы задач и абсолютные пользовательские пути. Обычный вывод `doctor` в терминале может показывать пути конфигурации и состояния; это не содержимое экспортируемого файла.

Экспорт создаёт новый файл с правами текущего пользователя и не перезаписывает существующий. Для повторного отчёта выберите другое имя. Общий JSON-вывод команды управляется флагом `--json`; при ошибке проверки команда возвращает ненулевой код завершения.

## Разработчику

- `diagnostics/history-verification.ts` читает по одной записи JSONL и использует те же валидаторы, что и хранилище. Этот модуль не содержит операций записи.
- `diagnostics/history-types.ts` задаёт общие схемы ответов `diagnostics.verifyHistory` и `diagnostics.rebuildIndex`.
- `diagnostics/export.ts` формирует отчёт через закрытый список полей и повторно проверяет его перед записью. Нельзя добавлять в него `Error.message`, произвольные `detail`, имена профилей или исходные RPC-параметры.
- Команды обслуживания принадлежат локальному интерфейсу человека. В MCP остаются только публичные инструменты запуска, статуса и отмены.
- Регрессии проверяются в `test/history-verification.test.ts`, `test/diagnostic-export.test.ts` и `test/doctor-command.test.ts`.
