# Первый запуск без настройки терминала

Harness выполняет задачи с помощью выбранной вами модели. Достаточно открыть приложение, выбрать папку и описать результат своими словами.

## Откройте приложение

Распакуйте проект в обычную папку своей учётной записи. Не запускайте его прямо из архива.

| Система | Файл запуска                                                                                                                                                          |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS   | Дважды нажмите **Запустить Harness.command**                                                                                                                          |
| Windows | Дважды нажмите **Запустить Harness.cmd**                                                                                                                              |
| Linux   | Откройте **start.sh** через пункт файлового менеджера «Запустить в терминале». Если такого пункта нет, откройте терминал в папке приложения и выполните `./start.sh`. |

Готовая поставка 0.7.0 уже содержит Node.js 24.21.0 и библиотеки. Выберите ZIP своей системы: Windows x64, Linux x64, macOS arm64 (Apple Silicon) или macOS x64 (Intel). Сразу после распаковки можно открыть учебное демо без сети и ключей. Запуск не устанавливает ничего в систему.

Архив `source.zip` предназначен для разработки. Его файл запуска загружает Node и зависимости, затем собирает приложение; для этого требуется интернет. [Различия поставок](portable-release.md).

Linux-архив рассчитан на glibc, а не Alpine/musl. Если macOS блокирует скачанный файл, используйте штатное открытие через контекстное меню; приложение не меняет защиту ОС.

## Пройдите три шага

1. **Папка.** Перемещайтесь стрелками и нажмите «Выбрать эту папку». Можно вставить полный путь из проводника. Файлы не нужно переносить в папку Harness. Если найдены авторские настройки проекта, мастер предложит использовать их.
2. **Подключение.** Выберите Codex, Qwen, OpenAI, Claude, Gemini или уже запущенную локальную модель. **Для Codex достаточно войти в аккаунт; ключ API не нужен.** Для стандартного облачного API адрес уже заполнен. Для Qwen доступны международный API, Китай и международный Coding Plan; выбирайте вариант своего аккаунта. Ключ вставляется в скрытое поле. В списке есть подсказка «У меня пока нет подключения · что выбрать?».
3. **Модель.** Если сервер предоставляет список, выберите модель стрелками. Иначе скопируйте её название из кабинета провайдера или настроек локального сервера. Получение списка не запускает генерацию и не гарантирует поддержку инструментов конкретной моделью.

По умолчанию ключ действует до закрытия окна. Можно выбрать «Сохранить» — тогда он хранится в защищённом хранилище ОС и подставляется при следующем запуске. При недоступном хранилище можно продолжить с ключом в памяти окна. Для удаления сохранённой записи замените ключ в настройках и выберите «Только это окно». Если ключ заранее задан в окружении сервиса, повторный ввод не требуется. API-ключи не записываются в настройки, историю или сообщения модели. Подписка на чат и доступ к API могут оплачиваться отдельно. Задачи и выбранные для контекста файлы отправляются провайдеру модели.

Неверный ключ можно заменить сразу в мастере. При проблеме со списком моделей есть повтор подключения, ручной ввод названия и возврат к выбору провайдера. Локальные модели мастер не устанавливает.

## Решите первую задачу

В поле сообщения **Enter** добавляет новую строку, **Ctrl+S** отправляет задачу, **Esc** сохраняет черновик и возвращает назад. Можно вставить несколько абзацев; сама вставка ничего не запускает. Стрелки перемещают курсор, рабочая папка остаётся в заголовке. Пустое сообщение не отправляется.

При следующем входе Harness предложит восстановить или удалить сохранённые черновики. Если отправка оборвалась, выберите **Повторить отправку**: сохранённый ключ защитит от повторного создания задачи. Если в беседе появился новый ответ из другого окна, Harness предложит перенести ваш текст после просмотра этого ответа. При недоступном сервисе Esc предлагает явный выход без последних несохранённых изменений; ранее сохранённый черновик остаётся. Полное удаление беседы удаляет связанные черновики, а общий сброс задач — все черновики.

Выберите **Новая задача**. Например:

> Изучи файлы в этой папке. Объясни структуру простыми словами и предложи следующие шаги.

Перед вводом проверьте строку **Рабочая папка этой задачи**. Упоминание другого проекта в сообщении само по себе не переключает папку: для этого откройте **Настройки → Недавние папки** или настройте другое подключение. Сервис запускается автоматически в том же окне. Второй терминал не нужен.

Мастер новых подключений включает подтверждение записи файлов и запуска программ. Перед записью файла показывается diff: красным — удаляемые строки, зелёным — добавляемые. Большие изменения можно дочитать по частям. Для программ показываются точные аргументы. «Нет» выбрано по умолчанию; «Да» разрешает только показанный вызов. Авторские конфиги проекта сохраняют собственные правила. Разрешённая программа работает с правами вашей учётной записи ОС.

Каждый раздел открывается на отдельном экране. Внутри задачи текст появляется постепенно. Tab переключает «Все», «Журнал», «Мысли» и «Ответ»; стрелки и PgUp/PgDn прокручивают историю, End возвращает к новым событиям. «Мысли» — пояснения, которые модель передала для показа. Некоторые модели их не предоставляют.

В заголовке задачи всегда видна её папка. Журнал показывает короткие результаты операций: найденные файлы, объём прочитанного текста и ошибки. После отмены вкладка «Ответ» сообщает об отсутствии итога, если модель ещё не прислала текст. Информационные страницы остаются на экране до нажатия Enter или Esc.

Статус **«Ответ получен»** означает, что модель закончила текущий ответ. Он может содержать уточняющий вопрос; выполнение всей задачи этим статусом не подтверждается. Выберите **«Ответить или продолжить»**, чтобы дать уточнение: исходная задача, предыдущий вопрос и результаты инструментов останутся в переписке.

После ответа или нажатия Enter доступны:

- **Ответить или продолжить** — ответить на уточнение модели или написать следующий вопрос с сохранённой перепиской;
- **Прочитать ответ** — открыть весь ответ с начала, с прокруткой и переносом строк;
- **Продолжить задачу** — после остановки или ошибки начать новый этап с сохранённой перепиской; готовый текст можно отправить Ctrl+S или изменить;
- **Продолжить после паузы** — возобновить тот же этап после проверки прерванных операций;
- **Сохранить ответ в папку проекта** — получить Markdown-файл; существующий файл не заменяется;
- **Оценить результат** — сообщить, что вы проверили или какая ошибка осталась;
- **Посмотреть изменения и восстановить файл** — вернуть состояние перед записью, если файл не меняли после Harness; новый файл при восстановлении удаляется.
- **Расход токенов задачи** — посмотреть потребление, сообщённое провайдером, и отдельную оценку Harness.
- **Предел шагов задачи** — выбрать на паузе, сколько шагов разрешить до следующей остановки для проверки.
- **Журнал, мысли и полный ответ** — открыть сохранённые события и продолжить наблюдение;
- **Убрать из списка** — скрыть этап, сохранив историю; активная работа сначала остановится;
- **Удалить навсегда** — удалить всю переписку, включая продолжения и связанные знания; перед подтверждением виден объём удаления;
- **Технические подробности** — посмотреть роли, расход токенов, версию опыта и причину сбоя.

В **Моих задачах** доступна вся история: общее количество, страницы и поиск по задаче, ответу или папке. Незавершённые задачи всегда сверху, даже при поиске. **Показать убранные задачи** открывает ранее скрытые записи. Их можно просматривать, проверять неизвестный результат операции или удалить переписку навсегда. Ответы сохраняются автоматически, даже если вы не экспортировали файл. Папка ответа — папка исходной задачи, в том числе после смены текущего проекта.

Карточка задачи, события и клавиши разделены рамками. Над каждым событием видны его название, время и роль. Если длинная запись не помещается целиком, при прокрутке появляется её заголовок с пометкой «продолжение». В **Технических подробностях** можно прочитать полный текст задачи и путь, посмотреть выполнение, изменения файлов и ошибки. Tab переключает раздел, стрелки прокручивают, Esc возвращает назад.

Данные на открытых экранах обновляются сами — обычно в течение секунды после изменения. Это работает и для событий из другого окна: новая задача появится в списке, её статус и расход изменятся, опубликованный урок попадёт в базу знаний. Выбранный пункт и место чтения сохраняются. Если выбранная запись исчезла, сначала выберите другой пункт стрелками. При потере связи Harness показывает последние данные и автоматически пробует подключиться снова; Esc позволяет вернуться. Ввод задачи, поиска и ключа остаётся под вашим управлением.

## Накопленные знания

Надпись **Без накопленного опыта** означает, что пока применяются только исходные инструкции. Это нормальное начальное состояние, а не ошибка.

В главном меню откройте **База знаний**. Здесь видны все уроки и сколько из них сейчас применяется. Можно найти урок по названию, роли, модели или папке, перейти на следующую страницу либо включить **Только применяемые уроки**. Неактивный кандидат остаётся доступен для просмотра, но не влияет на новые задачи.

Откройте урок и переключайте Tab три вкладки: **Урок**, **Доказательства**, **Оценка**. Длинный текст прокручивается стрелками и PgUp/PgDn; Home и End переходят к началу и концу. Enter открывает действия с уроком, включая сохранение в Markdown. Файл сохраняется в `~/.harness/exports/` или в `exports/` выбранного каталога состояния; точный путь появится на экране. Повторное сохранение не заменяет существующий файл.

Пункты **Вся очередь обучения** и **Версии и откаты** показывают задания и историю выпусков. Просмотр знаний не запускает модель. Приостановить и возобновить обучение можно через **Настройки → Самообучение**. Команда ручного отката описана в [README](../README.md).

## Клавиши и выход

| Где вы находитесь          | Действие                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------ |
| Меню                       | ↑ ↓ — выбрать, Enter — открыть, Esc — назад                                          |
| Ввод задачи или разрешение | Esc — отменить этот ввод и вернуться; разрешение не выдаётся                         |
| Выполнение задачи          | Esc — вернуться в меню, задача продолжает работать                                   |
| Выполнение задачи          | Ctrl+C — остановить текущую задачу и подзадачи                                       |
| Главное меню               | «Выход» или Esc — закрыть приложение; при активных задачах появится отдельный вопрос |

При выходе закрывается только сервис, запущенный этим окном. Если рабочий стол подключился к сервису другого окна, тот продолжит работу. После закрытия остаётся прощание **Harness by Ghost_Raven**: оно сообщает, остановлен сервис или продолжает работать в другом окне.

После аварийного закрытия некоторые задачи будут на паузе. Откройте задачу и выберите **Продолжить после паузы**. Если программа могла успеть изменить файл, сначала проверьте фактический результат. Пункт **Проверить прерванную операцию** доступен также после остановки задачи и у убранных записей. Ручная проверка сама не возобновляет работу. Неизвестная операция автоматически не повторяется.

Полное удаление убирает ответы, журнал, внутренние артефакты, копии для отмены изменений и зависимые уроки с их экспортами внутри Harness. **Файлы проекта и сохранённые вами ответы остаются.** Вернуть удалённую переписку нельзя. Удаление доступно после остановки работы и проверки неизвестных результатов; экран объяснит, если нужно дождаться обучения. Внутри остаются технические идентификаторы для защиты от повторного запуска и числовой учёт расхода.

## Настройки и помощь

**Настройки → Очистка данных** сначала предлагает выбрать состав: задачи и история, накопленные знания или оба раздела. Затем показывает количество записей и отдельное подтверждение с выбранным по умолчанию «Оставить». Настройки, подключения, ключи, файлы проектов и учёт расхода API сохраняются при любом выборе. Если удалить только задачи, сохранятся также знания и их доказательства: они могут содержать фрагменты прежних задач. Если очистить только знания, прежняя история задач останется, но автоматически извлекать из неё уроки заново Harness не будет. При активной работе или неизвестном результате операции экран объяснит, что нужно сделать перед очисткой.

**Настройки → Диагностический лог → Включить запись в файл** включает технический журнал для поддержки. Путь показан на экране; по умолчанию это `~/.harness/logs/harness.jsonl`. Переключатель сохраняется после перезапуска. Журнал ограничен тремя файлами по 1 МиБ; самые старые записи заменяются. Выключение останавливает запись, но оставляет уже созданные файлы.

Диагностический файл содержит технические события сервиса, завершение или ошибку задачи с её ID, имена команд, длительность и безопасные коды ошибок. Он не записывает тексты задач, ответы, аргументы инструментов, ключи и сырой вывод внешних программ. Подробная история задач по-прежнему хранится отдельно и содержит пользовательские данные.

В **Настройках** можно выбрать готовый профиль и папку проекта, заменить ключ, настроить другое подключение, приостановить самообучение или запустить диагностику. Самообучение расходует дополнительные запросы API. Без доказательств и контрольных задач новые рекомендации автоматически не применяются.

Выбор рабочего стола хранится в `~/.harness/desktop.json`; созданные мастером конфиги — в `~/.harness/projects/`. В Windows `~` означает папку вашей учётной записи. Точные пути всегда доступны через **Настройки → Где находятся настройки и история**. Если указан другой каталог состояния, данные находятся в нём.

| Что произошло             | Что сделать                                                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Подготовка не завершилась | Проверьте интернет и доступ к папке, повторите запуск. Подробности установки — `.tools/setup.log` в папке приложения. |
| API не принял ключ        | Откройте настройки ключа. Проверьте провайдера, регион аккаунта и доступ к модели.                                    |
| Ошибка лимита запросов    | Проверьте баланс/лимиты в кабинете провайдера и повторите задачу позже.                                               |
| Папка переехала           | Выберите существующую папку в настройках или настройте проект заново.                                                 |
| Сервис уже открыт         | Рабочий стол подключится к нему. Смену его подключения и ключа выполняйте в исходном окне.                            |

Оба направления подключения Codex описаны в [codex.md](codex.md). Расширенные команды и подключение OpenCode описаны в [README](../README.md). Для OpenCode можно оставить этот рабочий стол открытым: его сервис обслуживает MCP до закрытия окна.

## Проекты, модели и расход токенов

«Настройки → Недавние папки» возвращает сохранённое подключение. «Подключить другую модель» меняет модель без повторной настройки папки и правил. Переключение доступно после завершения текущих задач, в окне владельца сервиса.

Harness не ставит задачи и обучение на паузу из-за количества потраченных токенов. В «Настройках → Расход токенов» показаны данные провайдера и отдельная оценка Harness с запасом на ответ и повторы. Счётчик за день начинается заново в 00:00 UTC; это учёт расхода, без суточного предела. Денежную стоимость и ограничения аккаунта проверяйте в кабинете провайдера. Если задача была приостановлена прежней квотой, откройте её действия и выберите «Продолжить после паузы».

У Codex счётчик Harness является оценкой: app-server не предоставляет жёсткого ограничения токенов одного ответа. Точные лимиты аккаунта смотрите в Codex.

В разделе самообучения видно, настроены ли контрольные задачи. Без них кандидаты остаются неактивными; положительный ответ модели сам по себе не выпускает урок.

## Пауза после заданного числа шагов

Один шаг — итерация рабочего цикла модели. Шаги основной задачи и подагентов считаются вместе. В новой конфигурации установлен предел 256 шагов до паузы. Это повод проверить ход работы: задача сохраняется, а кнопка «Продолжить после паузы» разрешает следующую порцию того же размера.

Для новых задач число меняется через **Настройки → Предел шагов**. Для уже начатой — через **Предел шагов задачи** в её действиях после паузы. Общая история и счётчик выполненных шагов при продолжении сохраняются. Старые задачи сохраняют свой прежний предел, поэтому его можно отдельно увеличить перед продолжением.

Базовое значение находится в конфиге проекта, в `limits.turns`. Настройка из меню сохраняется в `iteration-settings.json` внутри каталога данных Harness и имеет приоритет для новых задач. Настройки действующей задачи хранятся вместе с её состоянием.
