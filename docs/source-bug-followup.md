# Повторная проверка исходного кода

Продолжение [аудита исходников](source-bug-audit.md) после [стабилизации сборки](release-stability.md). Проверены файловые инструменты, завершение задач, внешний MCP и отзыв накопленного опыта. Воспроизведения используют временные каталоги, управляемые ответы модели и локальные HTTP/stdio-серверы.

## Исправленные дефекты

1. **Запись через оборванную символическую ссылку.** `realpath` возвращал `ENOENT` и для нового файла, и для ссылки на отсутствующую цель. Вторая ситуация попадала в разрешённый сценарий создания файла: `fs.write` мог записать за пределами workspace или создать запрещённый `.env`. Теперь `safePath` проверяет саму запись через `lstat` и отклоняет оборванную ссылку до записи. Создание обычного файла и работа через разрешённые существующие ссылки сохранены. Проверка: `test/dangling-file-link.test.ts`, `test/file-changes.test.ts`.

2. **Раннее завершение повторной отмены и закрытия runtime.** Итоговый статус появлялся раньше завершения очистки исполнителя или обработчика завершения. Повторный `cancel` и `close` могли вернуть управление, пока эта работа ещё продолжалась. Они теперь ожидают сохранённый promise исполнения, сохраняя статус и результат задачи. Проверены отменённый запрос, успешное завершение и ошибка; все три новых теста воспроизводили прежний дефект. Проверка: `test/runtime-stop.test.ts`.

3. **Таймаут обнаружения MCP-инструментов.** Настроенный `tools.timeoutMs` передавался при подключении и исполнении, но не при `tools/list`. Зависшая страница каталога использовала таймаут SDK. Теперь каждая страница получает настроенный предел. Проверены зависания первой и второй страницы через реальный локальный HTTP-сервер. Проверка: `test/mcp-client-lifecycle.test.ts`.

4. **Потеря схемы результата при постраничном MCP-каталоге.** Установленный SDK очищает кэш схем при каждом `listTools`, поэтому неверные результаты инструмента с предыдущей страницы проходили без проверки. Harness сохраняет валидатор рядом с зарегистрированным инструментом и использует штатный `AjvJsonSchemaValidator` SDK. Проверены неверный результат, отсутствие обязательного `structuredContent`, корректный результат и варианты `isError` на обеих страницах. Новая проверка выделена в `src/mcp-client/output-validation.ts`.

5. **Продолжение оценки отозванного урока и потеря причины отзыва.** Отрицательная обратная связь во время первого сравнения оставляла ещё 11 ненужных запросов; затем техническая ошибка публикации затирала причину пользователя. Проверка отзыва перед следующим запросом останавливает оценку, а обработчик ошибки сохраняет уже неактивное задание. Отдельно проверены отзыв на последнем успешном и провалившемся сравнении, отсутствие публикации и сохранность причины после загрузки журнала. Уже отправленный запрос может завершиться. Проверка: `test/learning-feedback.test.ts`.

Дополнительно закреплён работающий сценарий: неизвестный исход первой записи останавливает следующие записи того же пакета. Исполнение второй записи не начинается; задача остаётся на паузе. Проверка: `test/tool-batch-failure.test.ts`.

## Проверки

Полный `npm run check` прошёл на Node 24.21.0: **86 файлов, 570 тестов** на каждой из двух систем — macOS arm64 и Linux arm64. Добавлено 17 проверок относительно предыдущих 553. Linux-контейнер запускался от пользователя `node` с отключённой внешней сетью. Хеши исходников и тестов совпадают между двумя прогонами; проверка целостности собранного приложения возвращает `true`.

Итоги полного прогона, версии, хеши исходников и логов фиксируются в [source-followup-check.json](source-followup-check.json). Общая команда — `npm run check`: совместимость зависимостей, форматирование, TypeScript, сборка с запуском CLI и весь набор тестов.

Первый общий прогон обнаружил несовпадение нового типа валидатора с объединением типов ответа `Client.callTool`. Сигнатура исправлена на официальный `CompatibilityCallToolResult`; дальнейшая проверка выполняется на этой версии исходников. Логи первого отказа сохранены отдельно от финальных результатов.

## Границы проверки

Облачные модели и нативная Windows в этом аудите не запускались. Работающий пользовательский сервис не перезапускался; собранные изменения используются после перезапуска Harness. Предыдущий ZIP выпуска остаётся отдельным историческим снимком и не содержит этих исправлений.

Проверка файлового пути закрывает воспроизведённый обход через уже существующую оборванную ссылку. Она не создаёт изоляцию ОС или атомарную защиту от внешней подмены файлов между системными вызовами.
